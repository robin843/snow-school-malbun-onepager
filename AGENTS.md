# Project rules

- Keep effective teaching-minute conversion in the pure display-only `src/lib/teachingDuration.ts`; derive group totals only from distinct validated teaching blocks and never import it into operational booking or pricing logic — why: public clocks and Core payroll/slot semantics must remain unchanged.

- Keep the header styling unchanged; use the sampled pastel yellow, ice blue, and blush palette throughout page content, with pastel yellow reserved primarily for calls to action.- Family course booking (YETI `course-booking`) lives in `src/lib/courseBooking/` (pure, node-testable) behind `VITE_FAMILY_BOOKING_ENABLED` (off by default) and the undeployed `course-booking-proxy` function; group courses have no capacity gate while private lessons require catalog tariff + instructor availability (`private.ts`), server quote is binding, YETI sends confirmation and invoice — why: core API not yet live and the website must never send booking mail or compute binding prices.
- Keep factual card projection in the pure, regression-tested `src/lib/productCardData.ts`, consuming the existing cached product catalog only; public offering metadata is display-only and replaces duplicate calendar/clock rows — why: prevent local overrides, name-derived schedules and duplicate duration labels without changing booking authorization.
- The legacy `/buchung` group reserve path must fail closed until Core provides a validated product-level `schedule_kind` sales contract with valid season/dates/blocks; the current `week` rendering fallback is not authorization — why: internal planning courses and product names cannot define a product's bookable schedule. The optional `availability_policy` does not supply that contract or override online eligibility. Private availability and the disabled family gate remain unchanged.
